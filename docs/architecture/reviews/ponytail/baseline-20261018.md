## Must fix

1. **Stopped work has no ordinary native resume action**
   (`successor/service/openai.ts:1098`, `successor/host/main.mjs:11`,
   `successor/apple/FortKit/Sources/FortKit/MacHostControl.swift:14`).
   - What this is: Stop records owner intent. A fresh core can resume only when
     its composition explicitly supplies `resumeOwnerHost`.
   - Problem: The bundled bootstrap always restores paused state, while native
     controls only enable startup or pair. After Stop, reopening the app cannot
     resume ordinary work. The successful resume in `host/owned-core.test.ts:116`
     is supplied by the fixture.
   - Fix: Add an explicit native resume operation for the exact owned host and
     test stop/reopen/resume through that operation. Keep automatic restore paused.
   - If we skip it: A normal user can stop work but cannot resume it from Fort.
   - Disposition: Open v1 blocker. Implement separately across the private host
     boundary; this report does not waive it or authorize persistent activation.

2. **Native CI omits required fixture inputs**
   (`.github/workflows/fort-quality.yml:47`,
   `successor/apple/FortKit/Tests/FortKitTests/MacAgentServiceTests.swift:199`,
   `successor/apple/FortKit/Tests/FortKitTests/MacHostJourneyTests.swift:26`).
   - What this is: The workflow runs Swift tests that launch authored synthetic
     processes and compiled Fort resources.
   - Problem: Several tests require `FORT_TEST_NODE`, guardian and core artifact
     paths, but CI defines none. The complete host journey is skipped without its
     resource path. That journey also always copies a Homebrew-specific libnode,
     whereas CI selects the official Node distribution.
   - Fix: Prepare the guardian/resources in the existing native job, pass explicit
     paths, and copy the Homebrew library only when that selected Node needs it.
   - If we skip it: CI fails before those behaviors run, and the packaged journey
     remains skipped even after unrelated failures are repaired.
   - Disposition: Fix in the bounded review follow-up. Remote runner availability
     and a real CI run remain unverified until an authorized push/run.

3. **Executor packaging accepts a destination it cannot represent exactly**
   (`successor/packaging/codex-executor-artifact.ts:10`).
   - What this is: The public builder writes a new executor directory.
   - Problem: A JavaScript path with an unpaired surrogate passes validation;
     filesystem UTF-8 conversion replaces it. The builder can write a different
     path than the caller selected. Core/host builders already reject this input.
   - Fix: Reject ill-formed Unicode before directory creation and add one public
     behavior regression asserting no output entries.
   - If we skip it: Exact destination selection differs between packaging APIs.
   - Disposition: Fix in the bounded follow-up, with an observed failing test first.
