## Repeatable installed test workflow — proposal awaiting enrollment authority

Use one reusable attended test-session controller with immutable per-session data
and a separate authorization record. Verify source/app/runtime hashes for each
session; a routine implementation revision does not require a new one-off launcher
or copied approval message. Retain all historical launchers as consumed evidence.
This proposal has not started a runtime or issued an enrollment credential.

Requested bounded scope for the existing UI operator, through the parent:

- Up to three supervised Mac test windows, each at most ten minutes including a
  final one-minute cleanup reserve; at most twelve synthetic plain-text turns per
  window. The operator may enter the fixed test text. One window includes app
  relaunch and one explicit service/runtime restart against its same new ledger.
- One fresh temporary Mac device enrollment per window. Its absolute credential
  deadline covers all restarts and cannot be extended. Preserve the existing native
  cache before pairing; keep each new session's transcript and redacted results.
- Existing ChatGPT sign-in, exact `gpt-6-astra`, pinned official Codex 0.157.1 and
  the current no-tool permission profile. Instruction-only test skills may be
  explicitly selected; no bundle script, tool or external action is enabled.
- At most three owned runtime launches per window, each within the ordinary
  300-second process ceiling and the shared work cutoff. Stop on unexpected
  permissions, identity mismatch, residue or cleanup failure. No auto-renewal,
  automatic retry of uncertain work or reuse of consumed packet roots.

The concrete credential decision is permission to create those fresh, expiring
Fort service enrollments and use the resulting device tokens in the existing native
Keychain path. Earlier credentials expired and their attempts are consumed. This
is not a request for new provider sign-in, copied provider credentials, persistent
service credentials, API spending, security configuration changes, public ingress,
remote hosting, startup services or deployment. Those gates are distinct from
routine local implementation and remain outside this proposal.

The installed sequence is: create Writer; send a remembered word and a contextual
follow-up; relaunch the app and verify identity/history; restart the service/runtime
within the same credential deadline and continue in that Home; exercise visible
cancellation/uncertainty recovery when the runtime provides that evidence; explicitly
invoke one reviewed instruction revision; inspect accessibility, screenshots and
redacted saved receipts; finish cleanup before expiry. Synthetic fault injection
continues to cover nondeterministic races without claiming they happened live.
